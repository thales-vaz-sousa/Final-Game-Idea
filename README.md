## 🌿 Fluxo de desenvolvimento

Para manter o projeto organizado, cada integrante deverá trabalhar em sua própria branch.

### Branch principal

```text
main
```

A `main` deve conter apenas versões estáveis do projeto.

### Branches de desenvolvimento

Exemplos:

```text
feature/player-movement
feature/enemy-system
feature/main-menu
feature/level-01
feature/ui
fix/collision-player
docs/gdd
```

---

## 💾 Commits

Os commits devem ser pequenos e descrever claramente o que foi alterado.

Exemplos:

```text
feat: adiciona movimentação do jogador
feat: adiciona sistema de vida
feat: cria menu principal
feat: adiciona primeira fase
fix: corrige colisão do jogador
fix: corrige transição entre fases
art: adiciona sprites do personagem
audio: adiciona efeitos sonoros
docs: atualiza README
```

---

## 🧪 Testes

Antes de enviar alterações para a `main`, o integrante responsável deverá testar:

* [ ] O jogo inicia corretamente;
* [ ] A alteração funciona;
* [ ] Não existem erros aparentes;
* [ ] A alteração não quebrou funcionalidades existentes;
* [ ] A versão do projeto foi salva corretamente.

## 👨‍💻 Regras da equipe

1. Cada integrante deve trabalhar em sua própria branch.
2. Não fazer alterações diretamente na `main`.
3. Antes de começar uma tarefa, atualizar a branch com a versão mais recente da `main`.
4. Fazer commits frequentes e objetivos.
5. Testar as alterações antes de enviá-las.
6. Não apagar ou substituir o trabalho de outro integrante sem conversar com a equipe.
7. Manter arquivos e pastas organizados.
8. Antes de fazer merge, verificar se existem conflitos.
9. A `main` deve permanecer funcional.
10. Grandes alterações devem ser discutidas pela equipe antes de serem integradas.
